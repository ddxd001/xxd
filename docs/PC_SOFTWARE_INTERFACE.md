# RA8P1 机器人上位机软件接口文档

本文档描述当前 RA8P1 固件与 PC 上位机之间的实际接口，用于重新实现上位机。本文以当前源码为准，不以早期设计方案为准。

| 项目 | 当前值 |
|---|---|
| 文档日期 | 2026-08-16 |
| 固件协议版本 | 3 |
| MCU 串口 | SCI0，P602/RXD0、P603/TXD0 |
| PC/LoRa 串口 | 115200 bit/s，8 数据位，无校验，1 停止位，无流控 |
| 传输方式 | ATK-MWCC68D LoRa 透明传输，半双工 |
| 多字节字节序 | 小端（Little Endian） |
| 固件遥测周期 | 200 ms，标称 5 Hz |
| 控制链路超时 | 最后一个有效控制帧超过 800 ms |

协议定义的源码入口：

- `src/robot_protocol.h`、`src/robot_protocol.c`：帧格式和 CRC。
- `src/robot_app.h`、`src/robot_app.c`：消息语义、状态、故障和遥测。
- `pc_controller/protocol.py`：当前 Python 编解码参考实现。

## 1. 通信方向与消息类型

| 类型值 | 名称 | 方向 | 载荷长度 | 用途 |
|---:|---|---|---:|---|
| `0x01` | CONTROL | PC → RA8P1 | 10 字节 | 运动命令和动作标志 |
| `0x02` | CONFIG | PC → RA8P1 | 4 字节 | v3 保留，当前固件忽略 |
| `0x81` | TELEMETRY | RA8P1 → PC | 85 字节 | 整机、舵机和故障遥测 |

固件没有独立 ACK 消息。CONTROL 是否被接受，需要通过遥测中的 `last_control_sequence` 判断。CONFIG 当前不会生效，也不会产生应答。

未知消息类型会被固件忽略。

## 2. 通用二进制帧

每个消息使用以下结构，不使用换行符或文本分隔符：

| 字节偏移 | 长度 | 类型 | 名称 | 说明 |
|---:|---:|---|---|---|
| 0 | 1 | `uint8` | Header 0 | 固定 `0xA5` |
| 1 | 1 | `uint8` | Header 1 | 固定 `0x5A` |
| 2 | 1 | `uint8` | Version | 当前必须为 `0x03` |
| 3 | 1 | `uint8` | Message Type | 见消息类型表 |
| 4 | 2 | `uint16` | Sequence | 小端序号 |
| 6 | 1 | `uint8` | Payload Length | 0～96 |
| 7 | 1 | `uint8` | Reserved | 发送时写 0 |
| 8 | N | `uint8[N]` | Payload | 消息载荷 |
| 8+N | 2 | `uint16` | CRC16 | 小端存放 |

总帧长为 `10 + Payload Length` 字节。

### 2.1 CRC16

CRC 使用 CRC-16/CCITT-FALSE 参数：

| 参数 | 值 |
|---|---|
| Polynomial | `0x1021` |
| Initial value | `0xFFFF` |
| Reflect input/output | false |
| Final XOR | `0x0000` |
| `"123456789"` 检查值 | `0x29B1` |

CRC 的计算范围从 Version 开始，到 Payload 最后一个字节结束，即：

```text
Version + Type + Sequence(2) + Length + Reserved + Payload(N)
```

帧头 `A5 5A` 不参与 CRC。计算结果在帧尾按低字节在前发送。

### 2.2 流式解析要求

串口一次读取可能得到半帧、多帧或带噪声的数据，上位机必须维护接收缓冲区：

1. 搜索 `A5 5A`。
2. 至少收到 8 字节后读取版本和载荷长度。
3. 版本不是 3 或载荷超过 96 时丢弃当前候选头并继续搜索。
4. 等到 `10 + N` 字节后校验 CRC。
5. CRC 正确才交给消息解码器；错误时重新寻找下一处帧头。
6. 不要假设一次 `read()` 恰好返回一帧。

## 3. CONTROL 控制帧（`0x01`）

载荷固定为 10 字节：

| 载荷偏移 | 长度 | 类型 | 字段 | 有效范围 | 方向定义 |
|---:|---:|---|---|---|---|
| 0 | 2 | `int16` | `vx` | -1000～1000 | 正值向车头 |
| 2 | 2 | `int16` | `vy` | -1000～1000 | 正值向左 |
| 4 | 2 | `int16` | `omega` | -1000～1000 | 正值逆时针 |
| 6 | 2 | `int16` | `lift` | -1000～1000 | 正值上升，负值下降 |
| 8 | 2 | `uint16` | `flags` | 位标志 | 见下表 |

固件会把四个命令分量分别钳制在 -1000～1000。它们是归一化命令，不是 mm/s、rad/s 或 rpm。

底盘三轮分别为 ID1 前轮、ID2 左后轮、ID3 右后轮。固件内部进行 120° 全向解算、整体归一化、最大轮速限制、死区和加速度斜坡，上位机不要自行发送单轮速度。

### 3.1 动作标志

| 位 | 掩码 | 名称 | 语义 |
|---:|---:|---|---|
| 0 | `0x0001` | ARM | 尝试使能 |
| 1 | `0x0002` | DISARM | 立即停用 |
| 2 | `0x0004` | HOME | v3 保留，当前固件忽略 |
| 3 | `0x0008` | CLEAR_FAULT | 尝试清除故障 |
| 4 | `0x0010` | CALIBRATE | v3 保留，当前固件忽略 |
| 5～15 | — | Reserved | 必须写 0 |

ARM、DISARM 和 CLEAR_FAULT 应作为“单帧脉冲”发送，下一控制帧将对应位清零。DISARM 可以为了安全重复发送。新上位机不得发送 HOME 或 CALIBRATE。

不要在同一帧组合多个动作标志。当前固件的处理优先级是：

```text
DISARM（立即返回）
  → CLEAR_FAULT
  → ARM
  → 更新运动命令
```

建议每次只发送一个动作，收到状态变化的遥测后再进行下一步。例如先 CLEAR_FAULT，确认进入状态 0 或 2 后，再发送 ARM。

### 3.2 使能条件

ARM 只有满足以下条件才会生效：

- 当前状态为 0（未使能/零点无效）或 2（未使能/零点有效）。
- `fault_bits == 0`。
- 四个舵机全部在线。

状态 0 允许使能底盘，但升降仍锁定。升降动作要求 `homed == 1`，不再要求软上限。

### 3.3 升降零点与软件下界

固件不再执行主动回零。每次整机上电前，操作者必须先将升降机构放到真实最低位置；固件启动时直接将多圈位置和保持目标设为 0，并令 `homed=1`。

当前版本不安装也不使用下限开关，P502/IRQ26 不连接。固件不读取该引脚，也不会根据其电平校零。下降只以逻辑位置 `lift_position <= 0` 为软件下界；因此上电位置必须是真实最低点，且该软件下界不能替代机械限位。ID4 运行中掉线会令 `homed=0`，重新上线和 CLEAR_FAULT 都不能恢复零点，必须断电、人工放回最低点并重新上电。

升降的逻辑坐标固定为向上为正：`lift > 0` 表示上升，`lift < 0` 表示下降，`lift_position` 上升时增加。非零 `lift` 直接映射为 ID4 速度；输入回到 0 时，固件捕获当前反馈位置作为 `lift_target` 并切换到主动位置保持。通信中断、停用或故障不会继续执行上一条手动升降速度。

### 3.4 控制帧示例

序号 `0x1234`，`vx=1000`，`vy=-1000`，其余运动为 0，并请求 ARM：

```text
A5 5A 03 01 34 12 0A 00 E8 03 18 FC 00 00 00 00 01 00 96 AE
```

序号 `0x1236`，零运动并立即 DISARM：

```text
A5 5A 03 01 36 12 0A 00 00 00 00 00 00 00 00 00 02 00 B6 9B
```

## 4. CONFIG 保留帧（`0x02`）

载荷固定为 4 字节：

| 载荷偏移 | 长度 | 类型 | 字段 | 说明 |
|---:|---:|---|---|---|
| 0 | 4 | `int32` | Reserved | 旧版软上限字段，当前无效 |

CONFIG 为保持 v3 帧编号兼容而保留。当前固件对任何状态下的 CONFIG 都直接忽略，不改变位置、目标或状态。新上位机不应发送该消息。以下旧版示例仍能通过 v3 帧解析，但不会产生动作：

```text
A5 5A 03 02 35 12 04 00 A0 09 00 00 2D BD
```

CONFIG 不会刷新控制链路年龄，也不会改变 `last_control_sequence`。

## 5. TELEMETRY 遥测帧（`0x81`）

遥测载荷固定为 85 字节。遥测帧自身的通用帧 Sequence 是 MCU 独立递增的遥测序号，可用于检测丢包；它与控制帧序号不是同一个计数器。

### 5.1 整体载荷布局

| 载荷偏移 | 长度 | 类型 | 字段 | 说明 |
|---:|---:|---|---|---|
| 0 | 1 | `uint8` | `state` | 整机状态枚举 |
| 1 | 4 | `uint32` | `fault_bits` | 故障位掩码 |
| 5 | 2 | `uint16` | `last_control_sequence` | 最后接受的 CONTROL 序号 |
| 7 | 2 | `uint16` | `link_age_ms` | 最后有效 CONTROL 的年龄，最大 65535 |
| 9 | 1 | `uint8` | `online_mask` | 位 0～3 对应 ID1～ID4 在线 |
| 10 | 1 | `uint8` | `warning_mask` | 位 0～3 对应 ID1～ID4 温度达到 60°C |
| 11 | 1 | `uint8` | `home_switch` | 兼容字段；未安装开关，当前固定为 0 |
| 12 | 1 | `uint8` | `homed` | 兼容字段；1 表示上电零点仍有效 |
| 13 | 4 | `int32` | `lift_position` | ID4 跨零展开后的多圈位置 |
| 17 | 4 | `int32` | `lift_target` | 升降保持目标位置 |
| 21 | 4 | `int32` | `upper_limit` | 兼容字段；当前固定为 0 |
| 25 | 2 | `int16` | `wheel_1_speed` | ID1 当前下发目标速度 |
| 27 | 2 | `int16` | `wheel_2_speed` | ID2 当前下发目标速度 |
| 29 | 2 | `int16` | `wheel_3_speed` | ID3 当前下发目标速度 |
| 31 | 12 | struct | `servo_1` | ID1 遥测块 |
| 43 | 12 | struct | `servo_2` | ID2 遥测块 |
| 55 | 12 | struct | `servo_3` | ID3 遥测块 |
| 67 | 12 | struct | `servo_4` | ID4 遥测块 |
| 79 | 6 | struct | `fault_snapshot` | 第一次舵机异常快照 |

`link_age_ms == 65535` 表示尚未收到控制帧，或年龄已经饱和。该字段只由有效且序号更新的 CONTROL 刷新；CONFIG、CRC 错帧、重复帧和旧序号帧不会刷新链路年龄。

### 5.2 整机状态枚举

| 值 | 名称 | 含义与允许操作 |
|---:|---|---|
| 0 | DISARMED_UNHOMED | 输出停止；底盘可以 ARM，升降因零点无效而锁定 |
| 1 | HOMING | v3 保留状态，当前固件不会进入 |
| 2 | DISARMED_HOMED | 输出停止；上电零点有效，可以 ARM |
| 3 | ARMED | 接受底盘与升降命令 |
| 4 | FAULT | 故障锁定；舵机状态故障可在安全稳定后自动清除，其他故障需 CLEAR_FAULT |
| 5 | CALIBRATING | v3 保留状态，当前固件不会进入 |
| 6 | RECOVERING | 舵机可恢复故障处理中，所有输出暂时停止 |

RECOVERING 期间固件保留底盘运动命令，但会立即清除手动升降速度并捕获升降保持目标。故障连续消失 500 ms 后会恢复 ARMED；单次恢复超过 3 秒会进入 FAULT。10 秒窗口内最多允许进入 RECOVERING 3 次，第 4 次可恢复故障会直接进入 FAULT。上位机应明显显示该状态，但不得自动发送 ARM。

### 5.3 故障位

| 位 | 掩码 | 名称 | 说明 |
|---:|---:|---|---|
| 0 | `0x00000001` | LINK_TIMEOUT | 活动状态下控制帧超过 800 ms |
| 1 | `0x00000002` | SERVO_OFFLINE | 任一舵机掉线；上电有 1500 ms 宽限 |
| 2 | `0x00000004` | SERVO_STATUS | 舵机状态、过温或恢复失败 |
| 3 | `0x00000008` | HOME_TIMEOUT | v3 保留，当前固件不会产生 |
| 4 | `0x00000010` | DRIVER_INIT | UART、定时器、IRQ 等初始化失败 |
| 5 | `0x00000020` | HOME_STALL | v3 保留，当前固件不会产生 |

FAULT 状态下一般四个舵机目标均为零。LINK_TIMEOUT 故障是例外：底盘仍为零，如果升降零点有效且反馈正常，固件会继续保持最后升降目标。

CLEAR_FAULT 只有在四个舵机全部在线且当前没有严重状态位时才成功。清除成功后进入状态 0 或 2，不会自动恢复 ARMED。

当 FAULT 中只有 `SERVO_STATUS` 故障位且它不是真实过温故障时，固件会自动检查恢复条件。四个舵机全部在线、严重和可恢复状态均消失并连续稳定 2000 ms 后，固件自动清除实时故障位、重新请求开启力矩并进入状态 0 或 2。该流程不会自动 ARM，也不会恢复故障前的运动命令；故障快照保留用于诊断。已确认的真实过温故障不会自动清除，温度下降后仍需人工 CLEAR_FAULT。

### 5.4 单个舵机遥测块

每个舵机块 12 字节，块内偏移如下：

| 块内偏移 | 长度 | 类型 | 字段 | 单位/说明 |
|---:|---:|---|---|---|
| 0 | 1 | `uint8` | `online` | 0 掉线，非 0 在线 |
| 1 | 1 | `uint8` | `protocol_error` | STS 响应包错误字节，简称 E |
| 2 | 1 | `uint8` | `status_flags` | STS 状态寄存器，简称 S |
| 3 | 1 | `uint8` | `temperature_c` | °C |
| 4 | 1 | `uint8` | `temperature_limit_c` | 舵机内部温度上限；0 表示尚未读到 |
| 5 | 1 | `uint8` | `voltage_tenths` | 0.1 V；显示值为字段除以 10 |
| 6 | 2 | `int16` | `position` | 舵机原始位置反馈，单圈/方向解码后的 counts |
| 8 | 2 | `int16` | `speed` | STS 原始速度单位 |
| 10 | 2 | `int16` | `current` | STS 原始电流单位 |

位置、速度和电流当前均按固件解码后的原始整数传输。若新上位机要显示物理单位，应单独增加明确的型号换算配置，不能直接把这些值标成 rpm、A 或角度。

`protocol_error` 与 `status_flags` 使用相同的位定义。显示故障时应先进行按位或：

```text
servo_flags = protocol_error | status_flags
```

| 位 | 掩码 | 名称 |
|---:|---:|---|
| 0 | `0x01` | 电压异常 |
| 1 | `0x02` | 传感器异常 |
| 2 | `0x04` | 温度异常 |
| 3 | `0x08` | 电流异常 |
| 4 | `0x10` | 角度异常 |
| 5 | `0x20` | 过载异常 |
| 6～7 | `0xC0` | 未定义/未知异常，按严重故障显示 |

电压、电流和过载位在 ARMED 状态下按可恢复故障处理，传感器、角度和未知位按硬故障处理。由于当前 ID4 在约 40°C 时误报温度状态位，且观察到温度从约 39°C 单帧跳到 125°C，该状态位和单次高温值只保留作诊断及快照。只有 `temperature_c >= 70` 连续保持 500 ms 才确认真实过温、进入硬故障并锁存到人工清除。

### 5.5 舵机故障快照

偏移 79 的 6 字节结构：

| 快照内偏移 | 长度 | 类型 | 字段 | 说明 |
|---:|---:|---|---|---|
| 0 | 1 | `uint8` | `valid` | 0 无快照，非 0 有效 |
| 1 | 1 | `uint8` | `servo_id` | 1～4 |
| 2 | 1 | `uint8` | `protocol_error` | 触发时 E 值 |
| 3 | 1 | `uint8` | `status_flags` | 触发时 S 值 |
| 4 | 1 | `uint8` | `temperature_c` | 触发时温度 |
| 5 | 1 | `uint8` | `temperature_limit_c` | 当时读到的舵机温度上限；0 表示未知 |

快照记录本次锁存周期中遇到的第一个舵机原始异常，直到 CLEAR_FAULT 成功才清除。自动恢复成功会清除 `SERVO_STATUS` 故障位，但不会清除快照，因此“故障位为 0、快照仍有效”是合法状态。新上位机应把实时状态和历史触发快照分开显示。

## 6. 16 位控制序号

固件只接受比上一个 CONTROL 更新的序号，判断逻辑等价于：

```c
(int16_t) (new_sequence - previous_sequence) > 0
```

因此：

- 相同序号会被丢弃。
- 较旧序号会被丢弃。
- `65535 → 0` 的正常回绕可以接受。
- 单次向前跳跃应小于 32768。
- 被丢弃的 CONTROL 不会刷新 800 ms 链路看门狗。

上位机进程重启时，MCU 仍保留旧会话的最后序号。正确的重连流程是：

1. 打开串口后先只接收遥测。
2. 从首个有效遥测读取 `last_control_sequence`。
3. 设置本地下一发送序号为 `(last_control_sequence + 1) & 0xFFFF`。
4. 第一条 CONTROL 使用零运动和 DISARM。
5. 之后每发送一个 CONTROL，本地序号加 1。

如果每次启动都从 0 发送而不做同步，固件可能把命令当作旧帧持续丢弃，表现为“串口有数据但机器人不响应”。

## 7. 半双工发送时序

ATK-MWCC68D 当前按半双工透明传输使用。RA8P1 每 200 ms 尝试发送一次遥测；PC 若无间隔地持续发送，可能与遥测碰撞或堵塞 USB/LoRa 缓冲区。

当前 Python 上位机采用以下兼容时序：

```text
收到首个遥测，建立 200 ms 周期基准

周期开始   +20 ms          +70 ms                       +200 ms
   │          │               │                              │
   └──────────PC 发送槽 1─────PC 发送槽 2────保持静默─────────┘
```

- 每 200 ms 只有两个 PC 发送槽，平均 10 帧/s。
- 两个发送槽相隔 50 ms。
- 两个发送槽均发送 CONTROL；当前上位机不再发送 CONFIG。
- 其余时间保持静默，让 RA8P1 的 5 Hz 遥测通过。
- 任意两条有效控制帧的间隔必须始终小于 800 ms。

新上位机首版建议保持该时序。若以后提高控制率，需要同时实测两只 LoRa 的半双工切换、缓存和遥测丢包情况，不能只修改 GUI 定时器。

## 8. 推荐的上位机连接状态机

```text
DISCONNECTED
    │ 打开 COM，115200 8N1
    ▼
WAIT_TELEMETRY
    │ 收到 CRC 正确、版本 3、长度 85 的遥测
    ▼
SYNC_SEQUENCE
    │ next_seq = last_control_sequence + 1
    ▼
SAFE_DISARM
    │ 发送零运动 + DISARM
    ▼
READY_DISARMED
    │ 用户明确操作 ARM
    ▼
ACTIVE
```

建议把串口接收、协议解析、控制输入和 UI 显示分层，并保证只有一个发送器负责给帧分配序号，避免多个线程产生重复或乱序序号。

### 8.1 必须保留的安全行为

- 连接建立后不自动 ARM。
- 故障清除、LoRa 重连、手柄重连和 MCU 重启后不自动恢复运动。
- 窗口失去焦点、手柄断开、串口准备关闭或程序退出时，清空运动输入，并发送至少 3 个“零运动 + DISARM”帧，帧间隔约 50 ms。
- Space/停车按钮应绕过普通发送槽，立即发送一帧零运动 + DISARM，随后再补发安全停用帧。
- 未收到首个遥测并完成序号同步前，禁止发送 ARM 和运动命令。
- 遥测超过 1 秒未更新时，UI 应显示遥测失联、禁止使能，并尝试发送安全停用帧。
- 每次整机上电前，必须提示操作者先把升降机构放到真实最低位置。
- UI 不提供 HOME、CALIBRATE、软上限或 CONFIG 操作入口。
- 输入值在编码前再次钳制到 -1000～1000。

## 9. 当前按键和手柄映射

这些映射不是线协议的一部分，但新上位机若要保持操作兼容，可沿用：

| 输入 | 功能 |
|---|---|
| W / S | `vx` 正 / 负 |
| A / D | `vy` 正 / 负 |
| Q / E | `omega` 正 / 负 |
| R / F | `lift` 正 / 负 |
| Enter | ARM/DISARM 切换 |
| Space | 立即 DISARM |
| 手柄左摇杆 Y/X | `vx` / `vy` |
| 手柄右摇杆 X | `omega` |
| 右/左肩键 | `lift` 正 / 负 |
| Start | ARM |
| B | DISARM |

底盘默认速度比例为 20%，升降默认速度比例为 60%，手柄死区为 0.12。上位机先把输入归一化到 -1～1，底盘比例只应用于 `vx/vy/omega`，升降比例只应用于 `lift`，之后分别乘 1000 编码。升降比例范围为 10%～100%，步进 5%。

## 10. 本地配置兼容

当前 Python 程序使用 `pc_controller/controller_config.json`，默认结构如下。它只属于 PC 本地配置，不通过无线发送完整 JSON：

```json
{
  "com_port": "COM16",
  "baud": 115200,
  "speed_scale": 0.2,
  "lift_speed_scale": 0.6,
  "gamepad_deadzone": 0.12,
  "gamepad_axes": {
    "left_x": 0,
    "left_y": 1,
    "right_x": 2
  },
  "gamepad_buttons": {
    "left_shoulder": 4,
    "right_shoulder": 5,
    "start": 7,
    "stop": 1
  }
}
```

新上位机可以更换配置格式，但应继续持久化 COM 口、底盘速度比例、升降速度比例、手柄死区和手柄映射。旧配置缺少 `lift_speed_scale` 时使用 0.6；旧配置中的 `upper_limit_counts` 应忽略。

## 11. 上位机重构验收清单

- 能从任意分段的串口数据中恢复并解码帧。
- CRC 错帧、错误版本、未知类型和错误长度不会更新 UI 控制状态。
- CONTROL 的编码字节与本文示例一致；旧 CONFIG 帧可以解析但不会发送。
- 重连后使用遥测同步控制序号，第一帧为 DISARM。
- 能显示 7 种整机状态、6 个故障位和 4 个舵机的完整遥测。
- 分开显示实时舵机状态与锁存故障快照。
- 能确认 CONTROL 已被 MCU 接受，而不是只确认串口写入成功。
- 保持 200 ms 半双工周期及两个发送槽，连续运行时遥测稳定。
- 停止发送后，机器人在 800 ms 后进入 LINK_TIMEOUT；UI 能正确显示。
- 窗口失焦、手柄拔出、串口异常和程序退出均发送安全停用。
- 上电零点为 0；没有下限开关，逻辑位置 `<= 0` 时禁止继续下降。
- R/右肩键令机构上升且位置增加，F/左肩键令机构下降且位置减小；松键后捕获当前位置并保持。
- 底盘速度比例不会缩放升降命令，升降速度比例不会缩放底盘命令。
- ID4 掉线后零点失效，重新上线与清故障不能恢复升降，重新上电后才恢复。
- HOME、CALIBRATE 和 CONFIG 兼容帧不会产生动作。
