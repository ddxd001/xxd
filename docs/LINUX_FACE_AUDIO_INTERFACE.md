# Linux 屏幕与扬声器串口接口

## 硬件连接

RA8P1 使用 SCI1，Linux 使用 UART4。两端都是 3.3 V TTL、9600 bit/s、8 数据位、无校验、1 停止位、无流控。

| RA8P1 扩展板 | Linux 开发板 | 状态 |
|---|---|---|
| P8-5 / P400 / TXD1 | Pin 10 / UART4_RX | 必接 |
| P10 任一 GND | Pin 6 / GND | 必接 |
| P8-8 / P401 / RXD1 | Pin 8 / UART4_TX | 首版不接 |

两块板分别供电，不连接 3.3 V 或 5 V 电源轨，不得使用 RS-232 电平。Linux 设备节点为 `/dev/ttyS4`。

## Linux 接收格式

每次命令严格为一个原始二进制字节，不包含帧头、长度、CRC、换行或 ASCII 十六进制文本。

| 字节 | 动作 |
|---:|---|
| `0x00` | 待机 |
| `0x01` | 启动 |
| `0x02` | 欢迎回家 |
| `0x03` | 机器人移动中 |
| `0x04` | 请缓慢移动 |
| `0x05` | 请停止 |
| `0x06` | 开始充电 |
| `0x07` | 充电完成 |
| `0x08` | 检测到儿童 |
| `0x09` | 任务完成 |
| `0x0A` | 安全停靠 |

`0x0B`～`0xFF` 无效。重复的有效代码会重新开始对应的表情和语音；若多个字节同时积压，Linux 端只执行最后一个有效字节。

## 系统行为与诊断

- 上电不自动发送事件，Linux 保持自己的默认待机状态。
- 上位机通过 LoRa v3 的 `FACE_EVENT (0x03)` 提交事件；RA8P1 校验后再发送单字节。
- Linux 不返回 ACK，因此上位机的“已发送至 RA8P1”不等于屏幕或扬声器已经执行。
- RA8P1 不自动重试，避免同一语音被重新播放。
- SCI1 初始化或发送失败不会影响底盘、升降、使能状态或故障状态。

在 Linux 上可用以下命令观察服务日志：

```bash
journalctl --user -u robot-face.service -f
```
