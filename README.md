# RA8P1 三轮全向底盘与升降控制

本工程使用 RA8P1 CPU0 和 FSP 6.5.0 裸机状态机，控制 3 个底盘 STS3215 与 1 个升降 STS3215。LoRa 使用 SCI0（115200），URT-2 舵机总线使用 SCI8（1 Mbps），Linux 屏幕/扬声器使用 SCI1（115200），GPT0 提供 1 ms 时基。升降机构不安装下限开关，P502 不接。

## 硬件接线图

当前工程生成的 FSP 配置以 `configuration.xml` 为准：LoRa 使用 **SCI0**，舵机总线使用 **SCI8**，Linux 屏幕/扬声器使用 **SCI1**。不要按早期设计中的 SCI9 接线。

### 系统连接关系

```text
 PC（上位机）
      │ USB
      ▼
 LoRa A（电脑端）  ))) 无线透明传输 (((  LoRa B（机器人端）
                                             │ TXD/RXD/GND
                                             ▼
                                      RA8P1 扩展板
                                      ├─ SCI0：LoRa
                                      ├─ SCI8：URT-2
                                      └─ SCI1 TX：Linux UART4_RX
                                             │
                                             ▼
                                           URT-2
                                             │ STS 单总线
                         ┌───────────┬───────────┬───────────┬───────────┐
                         ▼           ▼           ▼           ▼
                     ID1 前轮    ID2 左后轮   ID3 右后轮   ID4 升降

 独立 12 V 电源 ── 保险/急停 ──► 四个 STS3215 的电源总线
```

### RA8P1 扩展板引脚

| 功能 | RA8P1 引脚 | 扩展板位置 | 连接对象 | 串口参数 |
|---|---|---|---|---|
| LoRa 接收 | P602 / RXD0 | P6-5 | LoRa B 的 TXD | 115200，8N1 |
| LoRa 发送 | P603 / TXD0 | P6-7 | LoRa B 的 RXD | 115200，8N1 |
| 舵机总线接收 | P500 / RXD8 | P4 | URT-2 的 `RX` | 1 Mbps，8N1 |
| 舵机总线发送 | P501 / TXD8 | P4 | URT-2 的 `TX` | 1 Mbps，8N1 |
| Linux 事件发送 | P400 / TXD1 | P8-5 | Linux Pin 10 / UART4_RX | 115200，8N1 |
| Linux 预留接收 | P401 / RXD1 | P8-8 | Linux Pin 8 / UART4_TX | 首版不连接 |
| 未使用 | P502 / IRQ26 | P4 | 不连接 | 固件不读取该引脚 |
| 信号地 | GND | P10 任一脚或扩展板其他 GND | LoRa、URT-2、Linux、电源负极 | 必须共地 |

> URT-2 的 MCU 接口丝印按该转接板定义采用同名连接：P501/TXD8 接 URT-2 `TX`，P500/RXD8 接 URT-2 `RX`。这里不要按普通串口模块的 TX/RX 交叉接法。

### 机器人端 LoRa 接线

| LoRa B 引脚 | 接到 RA8P1 | 说明 |
|---|---|---|
| TXD | P6-5 / P602 / RXD0 | LoRa 发、MCU 收，因此交叉连接 |
| RXD | P6-7 / P603 / TXD0 | LoRa 收、MCU 发，因此交叉连接 |
| GND | GND | 必须与 RA8P1 共地 |
| VCC | 符合模块铭牌要求的电源 | 不得接 12 V；先确认模块供电电压和极性 |
| AUX、M0、M1 等 | 按已保存的透明传输模式处理 | 固件不控制这些配置脚；不要悬空到不确定状态 |

电脑端 LoRa A 通过其 USB 转串口连接电脑。两只 LoRa 需要设置相同的信道、网络地址/组网参数、空中速率和串口格式；本工程串口侧固定为 115200、8N1。

### Linux 屏幕与扬声器接线

| RA8P1 扩展板 | Linux 开发板 | 说明 |
|---|---|---|
| P8-5 / P400 / TXD1 | Pin 10 / UART4_RX | MCU 发、Linux 收，单向连接 |
| P10 任一 GND | Pin 6 / GND | 必须共地 |
| P8-8 / P401 / RXD1 | Pin 8 / UART4_TX | 首版不连接，仅为以后双向通信预留 |
| 3.3 V / 5 V | 不连接 | 两块板分别供电，禁止互接电源轨 |

接口是 3.3 V TTL，不得接 RS-232 电平。Linux 使用 `/dev/ttyS4`、115200、8N1、无流控。上位机选择事件后，RA8P1 只向 Linux 发送一个原始字节 `0x00`～`0x0A`，没有帧头、换行和 ACK；详细命令见 [Linux 屏幕与扬声器接口](docs/LINUX_FACE_AUDIO_INTERFACE.md)。

### URT-2 与四个 STS3215 接线

| URT-2 一侧 | 连接 | 注意事项 |
|---|---|---|
| `TX` | RA8P1 P501 / TXD8 | 同名连接 |
| `RX` | RA8P1 P500 / RXD8 | 同名连接 |
| GND | RA8P1 GND | 必须共地 |
| V/DTR | 不接 | 不要由该脚给 RA8P1 或舵机供电 |
| 电平选择开关 | 3.3 V | 与 RA8P1 UART 电平一致 |
| STS 舵机接口 | ID1～ID4 的 STS 总线 | 按接口的信号、正极、负极丝印连接，严禁反插 |
| USB | MCU 控制时不接 | 防止 USB 串口与 RA8P1 同时驱动总线 |

四个 STS3215 并联在同一条总线上，必须提前分别设置为互不重复的 ID：ID1 前轮、ID2 左后轮、ID3 右后轮、ID4 升降。舵机电源线应采用适合电流的线径，不要让四只舵机的工作电流流经 RA8P1 开发板。

### 12 V 电源、急停与共地

```text
 12 V 电源正极 ── 保险 ── 急停常闭触点 ──► STS3215 电源正极
 12 V 电源负极 ──────────────────────────► STS3215 电源负极
        │
        ├────────────────────────────────► URT-2 GND
        └────────────────────────────────► RA8P1 GND

 RA8P1 的 3.3 V/5 V 电源 ──X──► STS3215 电源正极
 12 V 电源正极             ──X──► RA8P1、LoRa UART 或 GPIO
```

舵机使用独立 12 V、建议至少 15 A 的电源，并在靠近电源的位置串联保险和可切断 12 V 的急停。所有通信设备必须共地，但不要把 12 V 正极接入 RA8P1、LoRa 信号脚或 URT-2 的 MCU 电源脚。

### 升降下端输入

当前版本不安装也不使用升降下限开关，P502/IRQ26 保持不连接。固件不会读取该引脚、不会因其电平校零，也不会把它用于下降保护；遥测中的旧下限开关兼容字段固定为 0。

### 升降上电要求

固件不再主动回零，也没有软上限。**每次给 RA8P1 和舵机上电前，必须由操作者先把升降机构放到真实最低位置。** 固件上电后直接把该位置作为 0。按住 R/F 时直接进行上升/下降速度控制，松键时捕获当前位置并主动保持；内部统一使用“向上为正”的速度和位置坐标。如果 ID4 运行中掉线，零点立即失效；重新接上线和清除故障也不会恢复升降，必须断电、重新放到底部再上电。

### 首次上电前检查

1. 断电测量 12 V 正极与 GND，确认没有短路；确认舵机插头极性一致。
2. 暂不接舵机 12 V，只给 RA8P1、LoRa 和 URT-2 逻辑侧供电，检查各设备之间已经共地。
3. 确认 URT-2 电平开关为 3.3 V，V/DTR 与 USB 均未连接。
4. 先只连接一只舵机并限流上电，确认能读取 ID、温度和位置后，再依次连接 ID1～ID4。
5. 把升降机构人工放到最低位置后再上电；将底盘架空，以 20% 速度确认三轮编号和方向及升降正负方向。

## 舵机一次性配置

先只连接一只舵机，通过 URT-2 工具分别设置并断电确认：ID1 前轮、ID2 左后轮、ID3 右后轮、ID4 升降；波特率 1 Mbps；四只均为 Mode 1 闭环速度模式。固件不会在每次启动时擦写这些 EEPROM 参数。

## 构建与烧录

在 e² studio 中打开 `configuration.xml` 可检查 FSP 外设，若修改配置请点击 **Generate Project Content**。随后选择 Debug 或 Release，执行 **Build Project**。可通过 Debug 自动下载，也可使用 Renesas Flash Programmer 选择生成的 `.srec` 文件直接烧录；Debug 输出为 `Debug/xxd.srec`，Release 输出为 `Release/xxd.srec`。

## PC 控制端

重新实现或调试上位机前，请先阅读[上位机软件接口文档](docs/PC_SOFTWARE_INTERFACE.md)。文档包含当前 v3 二进制协议、控制序号同步、85 字节遥测布局、状态/故障定义及 LoRa 半双工发送时序。

### 新电脑一键部署

在仓库根目录用 PowerShell 运行 `pc_controller/setup.ps1`，自动完成：Python（缺失时用 winget 安装）→ `requirements.txt` 依赖 → Git for Windows → Kimi Code CLI（官方脚本）→ 聊天技能（`skills/ra8p1-robot` 和 `skills/box2robot-skills` 都已收进仓库，脚本直接复制到 Kimi Code 用户目录）→ 聊天工作目录。脚本只装环境，以下三步需手动：Kimi Code 首次登录（运行 `kimi` 后输入 `/login`）、Box2Robot 账号登录（`python ~/.kimi-code/skills/box2robot-skills/b2r.py login <用户名> <密码>`）、LoRa 的 CH340/CH343 驱动（Win10/11 一般自动安装）。固件构建烧录不在脚本范围，见下文"构建与烧录"。

```powershell
cd pc_controller
py -m pip install -r requirements.txt
py controller.py        # Tkinter 桌面版
py web_controller.py    # Web 版（苹果风格），浏览器打开 http://127.0.0.1:8080/
```

键盘为 WASD 平移、Q/E 旋转、R 上升、F 下降、Enter 切换使能、Space 立即停用。手柄 X/Y/A/B 依次发送“启动/开始充电/充电完成/安全停靠”事件；B 同时保留立即停用功能。底盘速度和升降速度分别调节，默认值为 20% 和 60%；首次方向测试仍应先把升降速度降到 20%。Web 和 Tkinter 版都可以从“表情/语音”列表手动发送 `0x00`～`0x0A` 事件；界面只能确认事件已送到 RA8P1，不能确认 Linux 已执行。Web 版另有触屏按住式按键、深色模式（标题栏月亮/太阳按钮，默认跟随系统，可用 `?theme=dark` 强制）、3D 预览（升降高度仅按控制输入模拟，不代表实际安全行程）、模拟机位摄像头浮窗（左腕/胸口/右腕三个按钮开关，可拖动、可缩放，接入真实摄像头后替换为视频流）、机械臂聊天助手（标题栏对话图标，把自然语言转发给本机 Kimi Code CLI 会话执行 Box2Robot 指令，上下文连续，可一键新会话）和遥测实时曲线（升降/轮速/温度，可暂停）。窗口失焦、串口关闭、手柄掉线或程序退出时会发送多帧零速停用命令。两个版本共用 `controller_config.json`，且协议与安全逻辑完全一致：Web 版的序号同步、200 ms 半双工发送槽和安全停用都在 `web_controller.py` 后端执行，浏览器只负责显示与输入。

舵机状态故障（包括 ID4 温度异常）进入 FAULT 后，固件会持续检查四个舵机。异常状态消失、四个舵机在线且连续稳定 2 秒后，自动清除实时 `SERVO_STATUS` 故障并回到未使能状态，但不会自动重新使能或恢复先前动作；故障快照继续保留，便于查看触发时的 ID、状态位和温度。

STS3215 的温度状态位在当前 ID4 上存在约 40°C 时误报，温度数值也观察到过从约 39°C 瞬间跳到 125°C 的单帧异常。因此温度状态位只作为遥测诊断，单次高温数值只记录快照；实际温度连续达到 70°C 满 500 ms 才确认过温并停机。确认后的真实过温故障不会自动清除，冷却后仍需人工 CLEAR_FAULT；传感器、角度和未知状态位仍按硬故障处理。

## 安全边界

当前版本没有下限位开关、上限位开关、软上限、急停反馈输入和断电防坠。下降仅依赖“上电前机构确实位于最低点”以及随后展开的编码器逻辑位置，编码器漂移或上电位置错误都可能导致机械越界；固件也不会阻止升降向上超过安全高度。首次测试必须空载、限制为 20% 速度并随时准备停机，升降机构不得在人员附近带载验收。
